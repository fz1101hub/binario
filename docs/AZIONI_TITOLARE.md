### Repository GitHub (impostazioni del titolare)

- **Protezione dei rami** (Settings › Rules › Rulesets, o Settings › Branches): per `main` e `stabilization/*` pull request obbligatoria, niente force push né cancellazione; per `stabilization/*` anche una revisione. Oggi GitHub riporta `protected: false` per ogni ramo, quindi un push diretto o un merge con la CI rossa sono possibili. **Non** rendere obbligatori i controlli dei singoli workflow (`android`, `ios`, `gtfs-assets`…): hanno filtri sui percorsi e su una PR che non li attiva resterebbero «in attesa» per sempre, bloccando il merge. Un controllo obbligatorio sensato richiede un workflow «gate» che parta su ogni PR e aspetti l'esito degli altri workflow dello stesso commit (lettura delle check run con `actions: read`); non è stato aggiunto perché va provato su GitHub (attesa dei workflow che partono dopo di lui, durata pari al workflow più lungo): da decidere se costruirlo o fidarsi della revisione delle PR.
- **Ramo `stabilization/resolve-alexa-audit-20261026`** (2 commit di ottobre, non unito): corrisponde al filtro push dei workflow e ai rami ammessi per la firma. Eliminarlo (o rinominarlo fuori da `stabilization/`). Lo stesso per gli altri rami senza PR con commit non uniti, se non servono: `analysis/realtime-source-20261027` (5 commit) e i tre `docs/audit-integration-*` (un documento ciascuno).
- **Vecchie pull request** ancora aperte (secondo audit, ci-tests-build): chiudere ed eliminare il ramo di #2, #5, #12, #13, #14, #15, #17, #18, #21, #22, #23, #24, #25, #26, #32, #33, #34, #35, #36, #39, #40, #41 (già interamente in `main`; restavano aperte perché la base non era `main`); chiudere #27 (famiglie di refresh token Alexa con una propria migrazione `0013_…`, superata da `main`), #43 (workflow che analizza l'APK di un'altra app: nulla si copia da altre app) e #44 (allarme fermata e schermate pendolari ora in `main` con altri nomi; resta l'idea «RFI su Alexa» come decisione di prodotto). Da decidere: #28 e #30 (test di isolamento del replay legacy: portarli se il percorso legacy resta, altrimenti chiudere; #28 modifica anche una migrazione già applicata) e #42 (palette verde e note di design, in parte per `voice-bridge/`, rimosso). Gli altri circa 40 rami già uniti si possono eliminare.
- **Pull request di Dependabot (#46–#63)**: da `.github/dependabot.yml` arriva ora una PR raggruppata al mese per ecosistema e nessuna per il Companion Expo. Chiudere #47–#51 (Expo, congelato); prendere #59 (Alexa, minori e patch, verde) e #46 (beautifulsoup4, serve a un solo strumento manuale) o chiuderlo; #54, #55, #57, #58 (GitHub Actions) in un'unica PR fatta a mano che aggiorni anche `.github/ci-inputs-lock.json` e `verifiedAt` (verificare che `wrapper-validation` v6 accetti ancora `min-wrapper-count`); #52, #53, #56 (Gradle, AGP 9.5, Gradle 9.8.2) solo dentro la migrazione pianificata della toolchain (plugin Kotlin, `compilerOptions`, compileSdk 37, metadata con il dispatch `refresh_dependency_metadata`, poi via le soppressioni Wear); #60, #61, #62, #63 (major di Alexa: plugin-react 6 vuole Vite 8, TypeScript 7 toglie `baseUrl`, lucide-react 1.x, react-day-picker 10) da pianificare o chiudere.
- **Cache della raccolta di puntualità**: ogni run di «Punctuality statistics» salva una nuova voce di cache (fino a 26 al giorno) e nessuna viene eliminata, così le voci spingono fuori dalla quota del repository le cache degli altri workflow. Eliminare la precedente dopo un salvataggio riuscito richiede il permesso `actions: write` per quel job (oggi nessun workflow ha permessi di scrittura): da decidere se concederlo.
- **APK in Git LFS**: 34 APK di debug e di vecchie release (31 in `archives/session-apks/`, circa 20 MB ciascuno, e 3 in `artifacts/v0.1.1*/`) occupano lo spazio LFS dell'account e sono scaricabili da chiunque. Se non servono più, spostarli in una release GitHub privata o altrove ed eliminarli dall'albero; lo spazio LFS si libera solo eliminando gli oggetti dalla storia (assistenza GitHub o un repository ricreato).
- **`local.properties` dentro un archivio di consegna** (secondo audit, security-privacy-5): il manifest `archives/session-versions/manifests/Binario-v0.12.0-consegna.txt` (riga 116) elenca `consegna_binario_v120/sorgenti/local.properties` dentro `archives/session-versions/Binario-v0.12.0-consegna.zip`, pubblico tramite Git LFS. Aprirlo (`git lfs pull --include=archives/session-versions/Binario-v0.12.0-consegna.zip`, poi `unzip -p archives/session-versions/Binario-v0.12.0-consegna.zip consegna_binario_v120/sorgenti/local.properties`). Se contiene solo `sdk.dir` (con il nome utente della macchina) basta rigenerare l'archivio senza quel file; se contiene password di firma o chiavi, considerarle esposte: revocarle o cambiarle, poi sostituire l'oggetto LFS e chiederne la rimozione dalla storia.
